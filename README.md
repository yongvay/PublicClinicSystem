Welcome to the TARUMT Public Clinic System! 👋

If you're reading this, you are likely evaluating our system or joining the 
development team. As the Systems Architect for this project, I want to give 
you a quick lay of the land so you can hit the ground running.

This application is a console-based Java system designed to automate and manage 
the day-to-day operations of a public clinic. We've built this with a strong 
emphasis on clean architecture, modularity, and object-oriented principles.

--------------------------------------------------------------------------------
 🏗️ 1. SYSTEM ARCHITECTURE & DESIGN PHILOSOPHY
--------------------------------------------------------------------------------
To ensure our codebase remains scalable and maintainable, we strictly adhere to 
the Entity-Control-Boundary (ECB) architectural pattern, augmented with Data 
Access Objects (DAOs) for persistence.

Here is how our layers communicate:
* Boundary (UI): Handles all user interactions. These classes only talk to 
  Control classes. No direct database access is allowed here.
* Control (Business Logic): The brains of the operation. These repositories 
  orchestrate data flow, enforce business rules, and communicate with both 
  Entities and DAOs.
* Entity (Data Models): Pure Plain Old Java Objects (POJOs). They hold the 
  data (e.g., Doctor, Patient) and have zero knowledge of the UI or Database.
* DAO (Data Access): Handles reading and writing to our flat text files. 

⭐ Special Note on Collections (ADT): 
We do NOT use Java's built-in Collections Framework (like java.util.ArrayList). 
Instead, we built our own generic Abstract Data Type (ADT) Custom `List<T>`. 
This demonstrates a deep understanding of data structures from the ground up!

--------------------------------------------------------------------------------
 🧩 2. CORE SUBSYSTEMS
--------------------------------------------------------------------------------
The application is divided into 5 independent but collaborating modules:

1. Patient Management: Handles patient registrations, medical histories, and 
   allergies.
2. Doctor Management: Tracks doctors, their availability, and specializations.
3. Medicine (Inventory) Management: Manages stock levels, reorder alerts, and 
   expiry tracking.
4. Room Management: Monitors the availability of Consult, Treatment, and 
   Observation rooms.
5. Appointment Booking (The Core): The central hub that ties everything 
   together. It assigns patients to doctors and rooms, handles waitlisting 
   logic when the clinic is busy, and deducts medicine stock upon discharge.

--------------------------------------------------------------------------------
 📂 3. PROJECT DIRECTORY STRUCTURE
--------------------------------------------------------------------------------
src/main/java/
 ├── ADT/              # Our custom generic List implementation & interfaces
 ├── Boundary/         # User Interfaces (Menus, Scanners, Console outputs)
 ├── Control/          # Repositories (Business logic and use-case orchestrators)
 ├── DAO/              # Data Access Objects (File I/O handlers)
 ├── Database/         # Text files (.txt) acting as our persistent storage
 ├── Entity/           # POJOs (Doctor, Patient, Appointment, etc.)
 ├── GeneratedReports/ # HTML/TXT reports automatically generated by the system
 ├── Main/             # The entry point (PublicClinicSystem.java)
 └── Utility/          # Shared helpers (Input validation, Date formatting)

--------------------------------------------------------------------------------
 🚀 4. HOW TO RUN THE APPLICATION
--------------------------------------------------------------------------------
Prerequisites:
- Java JDK 17 or higher.
- Apache Maven (The project uses a pom.xml for build management).
- An IDE like NetBeans, IntelliJ, or Eclipse (NetBeans is recommended as 
  nbactions.xml is provided).

Steps to run:
1. Open the project in your IDE.
2. Locate `Main.PublicClinicSystem.java` inside the `Main` package.
3. Run the file. 
4. The system will load existing data from the `Database` folder and present 
   the Main Menu in your console.

--------------------------------------------------------------------------------
 💾 5. DATA STORAGE & PERSISTENCE
--------------------------------------------------------------------------------
We use pipe-delimited (`|`) text files for storage (located in `Database/`). 
When the system boots up, the DAOs read these files and populate our custom 
ADT Lists in memory. When changes occur, the DAOs immediately write the updated 
state back to the files to prevent data loss.

If you ever need to reset the system, you can simply clear the data inside the 
`.txt` files (but keep the files themselves!).

--------------------------------------------------------------------------------
 📊 6. ANALYTICS & REPORTS
--------------------------------------------------------------------------------
Don't miss the reporting features! The system can generate both Console-based 
summaries and rich HTML visual dashboards (like the Medicine Expiry Report or 
the Doctor Specialization Chart). These are saved directly to the 
`GeneratedReports` folder. You can double-click the HTML files to view them in 
any web browser.
